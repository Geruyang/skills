# 配音、同步标记与播放兼容

## 先选择播放方式

需要同步标记时，先从上下文确认目标软件与用户对页数、编辑能力的要求。WPS、PowerPoint 和静态预览器不能当作同一个播放器。

| 情形 | 处理方向 |
|---|---|
| 静态讲解，没有配音要求 | 正常制作可编辑 PPT，不自动加入 TTS 或视频 |
| 配音与标记，已知 WPS 或播放器未知 | 优先考虑“每个讲解段对应一个静态标记步骤＋该段短音轨”，说明内容页与实际幻灯片数量 |
| 明确要求保持固定 N 张幻灯片 | 不可擅自扩成更多张；采用能在目标软件验证的媒体/动画方案，或者先说明具体方案与页数约束的冲突 |
| 对象动画随语音切换 | 音频与标记要使用可验证的共同起点，检查实际触发和播放时钟；仅写入毫秒延时不代表同步成功 |
| 另需可暂停、拖动或分享的观看版本 | 可附同一时间表生成的 MP4；不能用单独 MP4 冒充已修复用户要求的 PPT |

**已知案例的边界：** 2026-09-14 的工程 PPT 使用转场 WAV 和对象出现/消失时间节点，包结构、静态页面与配套视频均通过检查，但用户反馈 WPS 放映完全没有标记。之后改成 24 内容页、72 个静态放映步骤；每步一个可见黄框和对应短音轨，检查了全部步骤及原始 PCM 不变。当前证据只到文件与渲染验证，尚无用户确认或 WPS 实播成功记录。不能据此断言所有 WPS 都不支持对象动画，也不能把静态步骤方案记录为已经在 WPS 实播通过。

## 讲稿与音频

按有意义的区域拆段：表格的一行或相邻几行、代码的一个步骤、修改前后片段、页底结论。段数由页面内容决定，避免整页长音轨只移动一次框，也不要机械切成逐字高亮。

这里的“语音”是提供方无关的概念：可以使用用户录音、已经存在的音频文件、本地或系统 TTS、或任意声音插件。选择顺序为“用户给定音频 > 用户明确指定的提供方/音色 > 当前可用且适合任务的合成方案”。只有选定具体提供方后，才应用该工具的队列、字数、格式、任务状态和输出目录限制；不得把苏晴或其他单一音色写成通用流程的默认含义。

- 共用逐段结构：内容页号、段号、讲稿、目标区域、输出音频路径、任务 ID 和实际时长。
- 优先口语化解释含义；必要数值保持精确，少把长宏名、路径和十六进制代码直接交给中文 TTS 连续朗读。
- 使用选定的声音工具并保存可恢复的任务标识；查询既有任务到完成态后才认定完成，不重复提交状态不明的任务。若使用苏晴工具，遵守它当前的队列和字数上限，不另开模型进程；这些限制只是该提供方的规则，不推广到其他语音来源。
- 批量任务元数据及时落盘。Windows 中不要将越来越长的 JSON 放进 PowerShell 命令参数；曾因此超过命令长度上限。使用文件和短参数，或仅落盘必要字段。
- 按实际音频格式检查采样率、声道、位宽或编码、帧数、非静音程度和削波；不把这些数值检查声称为试听或转写核对。只有 AI 合成音色才需要说明其为合成参考音色，不能说成参考演员本人录制。

增量更新时，仅在讲稿及其当前语义均未改变时复用既有音轨；更改证据范围、数量或版本的段落应同步更新语音。插入新内容后重新映射物理步骤、内容页号、源码引用和目标区域，并核对最终嵌入媒体与复用原音轨的 PCM 或完整字节一致。讲稿字符串相等只是复用候选，不能自动证明语义仍适合当前版本。

## 时间与标记的绑定

以实际音频样本数作为唯一计时基线：`duration = frames / sample_rate`。在整数样本域累积段间停顿，最后才转换成毫秒或视频时间，避免逐段四舍五入产生累积漂移。停顿和入页等待可配置；历史使用的 0.25 / 0.35 / 0.50 秒只是一个案例，不是标准。

静态步骤方案的关键不变量：

1. 每一步都有且仅有本段的可见标记对象，不使用入场隐藏、对象出现/消失动画或旧时间树。
2. 该步内嵌的 WAV 只含该段讲稿及明确的前后静音；进入步骤时标记可见，同时启动音频。
3. 步骤停留时间至少覆盖该音轨的完整长度。自动计时翻页、手动进入下一段时，都必须切换到对应短音轨。
4. 拆分后保留内容页号，并用“讲解 n / m”帮助区分步骤；显式说明实际幻灯片数量变化。
5. 复制原生幻灯片时更新 presentation slide IDs、slide/notes relationships、content types 和文档页数元数据；原有内部跳转映射到正确的新步骤，不能静默丢弃。
6. 旧版整页音轨与对象动画不应残留，避免两条声音同时播放或标记被旧动画隐藏。

标记优先使用清晰边框；深色背景或复杂画面可加很低透明度的强调底色，只要不影响正文对比度。代码位置按最终实际渲染测量，尤其是混合中文注释、等宽英文代码和稀疏行号。曾出现封面文字、代码分号和下划线被边框碰到的情况；检查完整字形外缘，而不是只看行号高度。

## OOXML 处理与验证

在制作技能允许的工具中创建原生页面和标记对象；仅对媒体、关系、时间节点做必要的包处理。转场声音方案使用 `p:transition / p:sndAc / p:stSnd / p:snd` 与 audio relationship；这与对象动画 `p:timing` 是不同机制，不应假定二者自动共用一个可靠的播放时钟。

向已有幻灯片 XML 注入 `p:snd r:embed` 时，要检查 `p:sld` 根元素本身是否声明关系命名空间。图片等子节点上的局部 `xmlns:r` 不覆盖根级转场；只在全文搜索 `xmlns:r` 会生成“unbound prefix”的坏包。关系 ID 也应按当前关系文件中的完整、不透明字符串判重，不要假设已有 ID 都是连续的 `rIdN`。

修复或输出时分别验证：

- **内容与结构：** 所有原始代码/表格仍在，标记对象不 hidden，每步目标正确，关系可解析，ID 唯一。
- **媒体与计时：** 实际嵌入 WAV 与讲稿段一一对应，长度覆盖停留时间；复用既有音频时对比 PCM，防止误拼或重录。
- **渲染：** 最终包重新导入的所有步骤可见，文字无遮挡；静态步骤下无需动画渲染器就应看见当前框。
- **实际播放：** 在用户目标软件检查从头启动、段切换、页切换和手动导航。未实播就如实说明，不能说“WPS 已验证”。
- **视频（若生成）：** 使用同一段时间表。解码检查段开始之后与段中间的实际视频帧，而不只查看生成用的 PNG；允许帧率和编码产生的明确小误差，核对完整音轨时长。

用户报告“声音正常但没有框”时先确认软件、文件版本和现象。检查框是否仅在编辑模式可见、是否被入场动画隐藏、目标 ID 是否正确。若确认目标软件未播放标记动画，改用不依赖这些动画的交付方式；不要只重新导出同一时间树，再宣称修复成功。

用户报告“没有声音”时，分别检查媒体文件、播放触发和实际放映环境。已有音频非静音且一一对应时，先保留原音轨，排查静态预览、放映设置和播放节点。只有切换声音的结构可尝试普通嵌入媒体对象、入页自动播放与可点击的媒体入口；移除旧声音触发，防止叠播，确保控制不遮挡页底标记。2026-09-16已验证此修复的文件、关系、音轨字节及渲染，但尚未实播，不应宣称WPS兼容已通过。

## 感知能力与静帧字幕的补充检查

先确认当前身份能否感知真实音频。音频输入不可用时，不声称试听；插件complete、实际解码、实际ASR语义数字、字幕时轴和图面分别记录，按任务已授权的证据要求处置。ASR不等同人耳评价，关键疑义需复核或返工；英文名称无法确认时，可用清楚中文用途表达，并保留原名/资料ID映射。

FFmpeg稀疏concat幻灯片输入要先用fps展开连续帧，再渲染ass/subtitles；仅设置输出-r不能保证页内字幕更新。检查同一页不同cue的实际解码帧。若裁去无语音头部，保留原始音频、准确样本裁切位置和PCM对应；能量阈值只辅助定位，不能证明被裁内容没有语音。
