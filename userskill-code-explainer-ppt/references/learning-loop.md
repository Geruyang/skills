# 自动经验回写协议

本协议落实用户“每次为工程代码生成 PPT 学到的知识自动更新到这个 skill”的要求。由执行当前任务的助手在交付前完成，无需创建周期性自动化。

## 复盘与整理

每次生成、更新或故障修复结束时：

1. 重新读取个人目录的 `SKILL.md`、相关参考文档及 `experience.json`，不要用旧副本覆盖并行任务的改动。
2. 对照本次实际输出和用户反馈，找出改变以后决策的知识，例如：源码证据缺失、字体导致的行高变化、某播放器的实际失败、经实播证实有效的修复。
3. 去重后优先修订所属参考文件；新知识仅影响一个模式时不要写进通用入口。不要累积工程专有数值、完整源码或每次执行日志，把可复用原则与项目证据位置分开。
4. 保留证据等级：`user_reported` 为用户直接反馈；`artifact_verified` 为文件、渲染或媒体检查；`application_verified` 必须真的在指定软件中播放或收到用户明确成功确认；`hypothesis` 仅为推断。
5. 结论矛盾时，记录环境、版本与证据，不以最新一条猜测抹掉既有事实。失败和修复验证最好分成不同经验 ID，避免把失败事实覆盖成“已成功”。

## 每次都登记复盘

在当前工程构建目录写一个 UTF-8 JSON，再运行技能目录中的 `scripts/update_experience.py --input <绝对路径>`。脚本默认更新自己所属技能的 `references/experience.json`；不要在未来任务中运行本次工程里的安装暂存副本。

```json
{
  "review_id": "稳定的任务或产物标识-本次复盘版本",
  "date": "2026-09-14",
  "task": "工程代码讲解 PPT 修复",
  "result": "no_new_knowledge",
  "summary": "已复盘；没有新增可复用知识。",
  "lessons": []
}
```

确有新知识时，将 `result` 改为 `updated`，并提供已去重的经验：

```json
{
  "id": "播放器-具体现象或约束",
  "scope": "明确的软件、模式或环境",
  "observation": "实际看到了什么",
  "guidance": "下次应怎样改变处理",
  "evidence_level": "artifact_verified",
  "evidence": ["项目内报告路径、用户反馈所在任务或实播记录"],
  "limitations": "仍未验证的部分"
}
```

完整输入的 `lessons` 放置上述对象。使用稳定的经验 ID 合并同一结论；同一 `review_id` 重试时不能重复计数。新一轮真实反馈使用新的复盘 ID。即使没有新知识，也记录复盘日期和结果，明确实际执行了更新步骤。

`experience.json` 是去重后的知识证据账本，不是完整聊天记录。脚本保留最近 20 次复盘和累计次数，经验本身不会因日志轮换而丢失。经验多到影响检索时，人工合并重复项并同步参考文件；不要默默删掉仍然适用的知识。

## 验证与权限

更新完成后，检查 Markdown 链接、frontmatter、`agents/openai.yaml` 与引用的一致性，使用当前 skill-creator 的验证脚本；更改可执行脚本时验证真实行为与失败路径。

经验回写属于用户授权范围，但文件系统权限仍可能要求正常提权。出现限制时先保存项目内待回写内容，按执行环境的正常授权流程操作。仍不可写时在交付中说明具体未完成项，不能说“已自动更新”。不要修改别人的技能、插件缓存或扩大无关工具权限。
