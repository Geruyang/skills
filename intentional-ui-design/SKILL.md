# 知形 UI 设计

让视觉表达服务用户任务，同时形成清楚、可持续的产品辨识度。中文沟通为默认，尊重用户指定语言。

## 入口与范围

- 开始时简短说明使用本技能。读现有界面、品牌规范和相关代码，保留用户明确指定的技术栈与设计约束。
- 根据任务规模裁剪流程：修一个按钮或溢出问题，直接诊断、查询、修复和验证；新产品或整体改版才展开方向探索与设计系统。只要求方案时交付方案，不擅自实现或发布。
- 本技能负责设计决策和验收，UI UX Pro Max 提供检索依据。优先读取同级 `../ui-ux-pro-max/SKILL.md`；没有同级安装时检查当前个人技能目录。依赖缺失则明确说明，仍可完成概念方案，但不能声称使用了数据库。
- 来源与阅读边界见 [references/sources.md](references/sources.md)。工具调用和命令见 [references/pro-max-usage.md](references/pro-max-usage.md)。平台检查见 [references/platform-review.md](references/platform-review.md)，按目标平台读取。

## 1. 写清楚设计要解决什么

从用户请求、仓库和现有产品提炼一个短 brief：

- 谁在什么场景完成什么主要任务；当前最大的操作障碍是什么。
- 必须保留的信息与操作、平台、输入方式、现有组件库，以及代表性的真实内容长度。
- 想传达的感受及其具体表现，例如“可靠”对应稳定布局、清楚的数据来源、可预测的反馈，而非简单套用蓝色。
- 验收条件：用户能完成的关键操作、必须覆盖的屏幕尺寸和状态。

已能推断的内容直接形成合理假设并继续。只询问会改变设计方向的缺失信息。勿让用户先填一份完整问卷。

## 2. 有需要才探索方向

有明确品牌或成熟界面时沿用其语言；无既定方向的新设计，通常给出 2–3 个在信息布局和视觉重心上确实不同的候选。每个候选写清：主任务如何呈现、一个辨识特征、代价，以及适用场景。不要仅更换颜色。

可用摄影、印刷、建筑、材料或游戏美术作为灵感，转成可实现的构图、字号、留白和交互规则。随机种子仅用于用户鼓励探索或方案过度同质化时；通过实际随机工具生成，不把种子显示在产品中，不打乱导航语义和可访问性。

用户未要求先选方案时，自行推荐最契合任务的一项并推进。多方案只做足以比较的草图或关键区域，不默认完整实现多个应用。

## 3. 用检索和判断形成设计约束

首次使用本轮的 UI UX Pro Max 前阅读其入口。按 [检索方法](references/pro-max-usage.md) 执行最小相关查询：整体设计用 `--design-system`；局部问题用明确的 domain；实现细节用已确认的 stack。

核对返回条目是否适合实际产品。数据库结果是候选方案，不能覆盖用户品牌、现有界面语言和平台约定。例如检索给出营销页布局时，不能直接套到桌面工作台。

把选定方向落到可复用规则：

- 语义颜色及前景/背景配对、字体与中文回退、字号层级、间距、边框、圆角、阴影和动效。
- 组件状态：默认、焦点、按下/选中、禁用，以及任务涉及的加载、空态、错误和成功反馈。
- 主要操作与次要操作的层级、信息密度和响应方式。确实需要横向比较的数据表可局部横滚，避免页面整体被撑破。

已有 tokens 或 MASTER 时优先增量调整。小修复不建立新的设计文档体系；整体设计可记录 brief、决策和 tokens 到项目约定目录。检索记录与最终决策分开，不能把未审核的生成结果当成产品规范。

## 4. 实现主流程与恰当的表现力

先做覆盖主要用户任务的纵向切片，使用代表性数据检查内容，再扩展组件与页面。展示型网页可强调品牌视觉；高频桌面工具重视扫描、比较、键盘操作和可恢复的状态；移动端遵守触控、返回和安全区域习惯。

图片、插画、3D 或视频只有在有助于内容理解或品牌表达时加入。需要 AI 图像时使用可用的图像生成技能与工具，不能用代码形状冒充已生成的素材。视频与重动效按需处理，并给出静态或减少动画的退化方案。工具不可用时采用可实现的静态设计，清楚说明限制。

内容应像实际产品：文案帮助用户理解结果和下一步，避免无用途的解释段落；示例数据要可辨认，不能虚构客户评价、业务成绩或用户背书。

## 5. 看渲染结果，再做有边界的评审

能运行时打开真实界面，获取目标尺寸的截图并检查核心交互。代码正确、构建成功或已有截图文件，都不等于已经看过渲染结果。优先使用可用且符合环境规则的浏览器或桌面工具；无法运行时标注未做视觉/交互验证。

从用户任务与参考品质出发，指出最影响使用或观感的 1–3 个具体问题，写清所在区域、影响和修改方式。先修任务阻塞、可读性、溢出和状态缺失，再调节奏、比例和细节。

若用户或环境另行授权多 agent 工作，可让独立评审者只看当前截图、任务与设计 brief、目标尺寸和参考图，不提供实现辩护或之前的分数。未授权时由当前 agent 使用同一标准复查，不声称是独立评审；本技能不默认启动 subagent 或切换模型。

通常先进行 1–2 轮重点修正。仍有明显问题时继续修正必要缺陷；不以主观的“必须达到 9/10”启动无上限循环。停止条件是验收任务可完成、重要显示问题已解决、方向与约束一致，而不是模型自评分。

做一次删减检查：对容器、装饰、徽章、重复文案逐项判断其用途。删除没有帮助的部分，保留导航线索、可访问性标签、状态说明和必要风险信息。渐变、卡片、圆角等均按实际用途判断，不设一刀切禁令。

## 6. 交付可审查的结果

交付应与用户任务一致，简短说明：最终方向与理由；已实现的页面或组件；关键验证结果；仍未验证的部分。给出实际产物、预览或截图链接。仅做方案时用结构图、关键状态和 tokens 表达，不假装已有运行中的应用。

所有生成文件跟随当前项目的工作目录约定。技能所在目录只存技能自身资源，不存其他项目的截图、缓存或设计结果。
