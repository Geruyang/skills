# MCU 实时视觉与模型验证

## 固定输入与模型身份

先固定类别顺序、ROI、RGB565 字节序、颜色/灰度、缩放整数舍入及量化参数。用相同原始帧逐像素比对 Python 与 C，再比较训练框架、TFLite 和 MCU 主机后端。报告 top-1、logit 误差、置信度/分差过门变化；top-1 相同不代表 bit-exact。教师、最佳开发候选、用户批准归档及板内实际固件分别登记，使用 SHA 而非目录的“最新”字样关联。

## 先验证能学习，再投入完整训练

- 窄网络原生预训练权重与从宽网络截通道初始化不是等价条件。检查残差、通道映射、激活方差、ReLU6 饱和、主干梯度和小样本拟合；能加载、能跑两轮、能重载 logits 只证明执行链通。
- BN 的 affine 参数与 running statistics 分别记录。`model.train()` 可重新打开统计更新；冻结须在每次模式切换后确认。BN 校准只用 train，不以 validation/test 校准；卷积继续更新时，一次校准不能保证以后不饱和。
- 类平衡抽样同时报告各类配额、不同样本覆盖率与跨轮重复次数。小会话被过量重复时，可对照类内覆盖队列；不要把 EBVC 的每类 412 次推广为通用配置。
- 蒸馏教师和学生使用同一语义增强视图及对齐类别；确认 KD 温度、KL 权重、硬标签权重和引入时间。设置同初始化、同 BN 策略、同采样的监督对照；KD 引入前已共同退步时，先检查共同微调环节，不能单独归罪蒸馏。
- 精度最佳与 CE 最佳可能不同；预先确定选模、早停、最低学习率到达轮次。多 seed 用相同数据与规则比较；同一批视频帧反复验证不变成更多独立样本。仅在授权范围内使用 test，不为复验文件完整性重新评分 test。

## 实时性与业务分开测量

按同一 frame_id 配对捕获、预处理、推理、消费和显示记录；环形 trace 读取须检测 guard、半写记录、回绕及窗口开始前的旧记录。DWT 任务执行耗时、wall 时间、帧龄、吞吐和 LCD 像素刷新不是同一指标。

FIFO 导致结果陈旧时可评估 latest mailbox 和推理准入期限，单列主动丢帧/跳帧及吞吐代价。确认后处理、USB 分块和 CRC 计算有界，检查低优先级发送任务饥饿。避免以放宽时间/识别门限掩盖问题。

CCM 只供 CPU 可用数据；确认时钟、NOBITS/初始化及链接地址，DMA 缓冲仍放可访问内存。栈/堆不要和已有 RW+ZI 重复累计；MAC、参数量减少不能替代实板 arena 与延迟检查。

UNKNOWN 混合非目标手形和空背景时，只能叫“中性复位”，不能叫物理撤手检测。分类正确、持势确认、指令发出、UI 状态变化和 LCD 可见变化分别给证据。用户选择自行做手势验收时，完成其余已授权检查后交付，不反复要求摆姿。
